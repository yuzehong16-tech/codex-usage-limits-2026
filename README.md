# Codex额度不够怎么办？2026额度限制、重置和解决方法

Codex额度不够怎么办？先看限制类型；如果项目正在收尾、确认需要补充用量，可以通过（czdy.codexplus.vip）处理 Plus、Pro 或 Codex Credits 国内充值，支持微信、支付宝。

但不要一看到“用不了”就立刻下单。背后可能是五小时共享窗口到了、额外周限制触顶、套餐内含用量用完，或者另购的 credits 余额不足；原因不同，额度重置时间和解决方法也完全不同。

最快的处理方式是先打开 `Codex Settings → Usage Dashboard`；如果正在 CLI 中工作，可以先用 `/status` 看当前状态。确认限制类型后，再决定等待恢复、使用 reset、购买 credits，还是升级 Pro。

## 先用 30 秒判断是哪一种限制

可以按下面的顺序排查：

1.  **页面给出了几小时后的恢复时间**：通常先按五小时窗口处理，不必立刻买点数。
2.  **五小时窗口还有空间，但周用量已经接近或到达上限**：等待周窗口恢复，或评估 credits、Pro。
3.  **套餐额度已经触顶，页面出现 Add credits / Credits 入口**：说明账号可以用额外 ChatGPT credits 接着工作。
4.  **已经购买过 credits，但余额接近 0**：检查近期用量以及是否开启 Auto top-up。
5.  **账号里出现 banked reset 或邀请奖励**：它可以临时恢复一次用量，但不是固定套餐权益。

不要把这些状态都叫作“没 token”。Codex 的套餐限额、ChatGPT credits 和 API 账单是三套不同的计费与使用逻辑。

## 五小时窗口到了：先保存现场，等窗口恢复

[OpenAI 当前的 Codex Pricing 页面](https://learn.chatgpt.com/docs/pricing#what-are-the-usage-limits-for-my-plan)按模型给出五小时内可发送的本地消息范围。以 GPT-5.6 为例：

| 模型 | Plus | Pro 5x | Pro 20x |
| --- | --- | --- | --- |
| Sol | 15–90 | 75–450 | 300–1800 |
| Terra | 20–110 | 100–550 | 400–2200 |
| Luna | 50–280 | 250–1400 | 1000–5600 |

这不是固定次数。同样一条消息，面对小脚本和大型仓库时，消耗可能差很多。模型、上下文、推理、工具调用、检索与缓存都会影响实际用量。

如果只是五小时窗口到达，先让当前任务留下一个简短交接：已经完成什么、改了哪些文件、下一步运行什么命令。恢复后从这个交接继续，比重新让 Codex 扫描整个仓库更省额度。

## 周限制到了：不要靠不断开启新对话绕

官方在五小时限制后同时注明“可能存在额外周限制”，但没有公开 Plus、Pro 5x、Pro 20x 的固定每周 credits 数字。

网上常见的 Plus 约 1000 点、Pro 5x 约 5000 点、Pro 20x 约 20000 点，只是社区按 5 倍、20 倍做的统一估算，不是 OpenAI 承诺的周配额。遇到周限制时，开启新对话、换项目或重启客户端通常不会改变账号级窗口。

这时更有用的判断是：本周是否还有必须交付的任务。如果只是个人练习，可以等窗口恢复；如果项目正在收尾，才考虑用 credits 补短缺。

## 套餐用完后出现 credits：适合补明确的短期缺口

Plus 或 Pro 的套餐内含用量会先被消耗，触顶后才开始扣可用的 ChatGPT credits。[OpenAI 的学生 credits 页面](https://developers.openai.com/community/students)当前给出的换算锚点是 `2500 credits = 100 美元`，也就是：

-   25 credits 约等于 1 美元；
-   1000 credits 约等于 40 美元；
-   GPT-5.6 平均每条消息约 5–40 credits；
-   1000 credits 粗略对应 25–200 条平均消息。

这个范围很宽，说明 credits 更适合“还差一段测试、一次迁移、一个上线收尾”这种边界清楚的任务。若需求仍然模糊，直接补点数往往只是继续放大无效上下文。

## credits 明明买了却掉得很快，检查这四项

第一，是否开启了 Fast mode。GPT-5.6 和 GPT-5.5 的 Fast mode 会按标准模式的 2.5 倍消耗 credits；GPT-5.4 为 2 倍。

第二，是否让 Codex 长时间保留越来越大的历史上下文。一个对话越长，后面的消息不一定和第一条同价。

第三，是否同时使用图片生成、ChatGPT Work 或 ChatGPT for Excel 等共享 agentic 用量的功能。它们可能从同一份额度中消耗。

第四，是否每轮都让 Codex重新读取整个项目。把任务限制到目标目录、目标文件和验收命令，往往比换新对话更有效。

## 邀请奖励和 Tibo 重置能不能救急

部分账号会看到邀请好友、banked rate-limit reset 或临时额外用量。奖励形式、邀请人数和过期时间都以账号内活动弹窗为准。

X 上经常宣布 Codex 临时重置的人是 Head of Codex Thibault “Tibo” Sottiaux（[@thsottiaux](https://x.com/thsottiaux)）。这些重置确实发生过，但没有固定周期，不能当作长期用量方案。看到现成 reset 可以使用；没有的话，不建议把项目进度押在“等下一次重置”上。

## 最后按这个顺序处理

-   **五小时窗口到了**：保存任务交接，等恢复后继续。
-   **周限制到了但不赶交付**：等待窗口恢复，同时缩小下周任务范围。
-   **只差一个明确收尾任务**：购买 credits 比直接升级更灵活。
-   **每周都稳定触顶**：再比较 Pro 5x 或 Pro 20x。
-   **只做本地自动化、能接受按量账单**：评估 API key，单独设置 API 预算。

国内支付不方便时，可以再看 Plus、Pro 或 Codex credits 的国内充值路径。但购买前必须先确认自己缺的是哪一种额度，避免把 ChatGPT 会员、ChatGPT credits 和 API 余额买混。
